# Лабораторная работа 3 — Численное интегрирование (метод парабол)

## Задание

Нужно посчитать определённый интеграл **методом парабол (Симпсона)** и посмотреть, как ведёт себя погрешность при сгущении сетки.

В работе рассматриваются две задачи:

1. Тестовая:
   - функция `f(x) = 6 * x^5`;
   - отрезок интегрирования `[0; 1]`;
   - точное значение интеграла известно и используется для проверки реализации.

2. Основная:
   - функция `f(x) = x^(1/30) * sqrt(1 + x^2)`;
   - отрезки `[0; 1.5]` и `[0.001; 1.5]`;
   - нужно сравнить, как меняется поведение ошибки, если стартовать не из нуля (из-за особенностей функции возле 0).

Для каждой задачи нужно:

- реализовать формулу Симпсона;
- построить таблицу по разным числам разбиений `n`;
- оценивать погрешность по правилу Рунге и по отношению «старой» и «новой» ошибки;
- посмотреть, как долго порядок метода остаётся около 4 и в какой момент всё ломается из-за машинного округления.

## Что сделано


- Описаны две функции:
  - `f1(x)` — тестовая `6 * x**5`;
  - `f2(x)` — основная `x**(1/30) * sqrt(1 + x*x)`.

- Реализован метод парабол:
  - по заданным `a, b, n` строится равномерная сетка;
  - считается сумма по формуле Симпсона (значения функции в узлах + в серединах отрезков);
  - возвращается приближённое значение интеграла.

- Для каждой задачи запускается цикл по `n` (начиная с маленького, дальше — удвоения):
  - на каждом шаге считаются интегралы при `n`, `2n`, `4n`;
  - по ним считается:
    - оценка по **правилу Рунге** (для метода 4-го порядка);
    - отношение ошибок `K` — фактический «коэффициент уменьшения» при удвоении числа разбиений;
    - для тестовой функции дополнительно считается разность с точным интегралом.

- Результат оформляется в таблицу (через `PrettyTable`) со столбцами типа:
  - `n`;
  - значение интеграла;
  - оценка по Рунге;
  - при наличии — «точная» ошибка и теоретическая `O(h^4)`;
  - `K`, чтобы видно было, насколько метод ведёт себя как порядок 4.

В итоге скрипт показывает:
- что на тестовой функции метод парабол действительно даёт уменьшение ошибки примерно в 16 раз при каждом удвоении `n`;
- что для «проблемной» функции поведение ошибки на `[0;1.5]` и `[0.001;1.5]` заметно различается;
- и что при слишком мелкой сетке погрешность перестаёт уменьшаться красиво — начинают доминировать ошибки округления.
